## Duplicates, obsolete candidates and risks

- **D removed:** one redundant streaming SHA-256 body (`research96.sha256`), retaining the public alias and identical file digest. Potential repeated metrics, event identity and time parsing across historical cohorts **not merged**: these have different contracts or are pinned by source/manifests; replacing them without paired input/output proofs risks altering results.
- **D structural:** `apps/research_explorer96.py` was not a redundant app; moved intact to package as internal view module. Its default root must change from `parents[1]` to `parents[2]`; explicit `RESEARCH96_DATA_ROOT` continues to work.
- **E candidates:** no tracked Python file can yet be proved unreferenced *and* irrelevant to reproducibility. No speculative script deletion. `docs/research_explorer.md` and `reports/post_merge_integration_20261104.md` are superseded as current UI guidance, but serve as historical handoff/evidence; retain. No tracked F removal is justified; untracked generated files are ignored and left alone.
- **Documentation inconsistency:** old README mixed milestone-1/2 proposals, 24-lane and 96-lane studies, a historical seven-page UI, and outdated test totals. The old Explorer handoff's launch command now starts the new six-page app. `docs/data_contract.md` references missing `docs/milestone2.md` and includes pilot-era status text; as a shared proposal contract it was **not silently rewritten**. Report-specific pre-November-5 NO-GO statements remain valid only for the strict P3 gate at their date; inferred P1/P2 later ran separately. Tianhao artifacts embed older git identities and hashes; do not edit them for cosmetic consistency.
- **Scientific risks:** `recovery_confirmation_v1` != unimplemented Proposal `recovery_start_sustained_v1`; 24/96 events cannot be merged; a 2026 road snapshot is not a verified 2023 network. P1/P2 populations differ and P3 has zero approved links. No zero-fill of unknown neighbor speeds; no fake curves from aggregate AUC. Manifests may contain source-code hashes; changing training code would invalidate provenance. Large-data replay/training is resource-intensive and not a normal refactor acceptance check.
